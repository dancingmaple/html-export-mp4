API 参考

// exportVideo(options) → Promise<{ blob, filename, used, duration, frames }>

选项类型说明
render必填(ctx, t, frame, frames) => void每帧回调。t=当前秒（WC 下精确等于 frame/fps）。请画满整个画布，并只依赖 ctx 与 t，便于预览/导出复用。
width / height必填number输出像素，库自动对齐到偶数（H.264 硬性要求）。
fps必填number帧率，常用 24 / 30 / 60。
duration必填number总时长（秒）。总帧数 = ⌈duration·fps⌉。
mode'auto'默认 'auto'。先 WebCodecs，失败回退 MediaRecorder。可强制 'webcodecs' / 'mediarecorder'。
bitratenumber默认按像素自动算（2–24 Mbps 钳制）。越大越清晰越大文件。
filenamestring默认 'video-export'。扩展名按引擎自动加 .mp4 / .webm。
downloadboolean默认 true。设 false 则只返回 blob，自行处理。
onProgress(p, info) => voidp∈[0,1]；info 含 frame/frames/t/used，用来画进度条。
signalAbortSignal传入即可随时 abort() 取消，抛 AbortError。
alphaboolean默认 false。H.264 不含透明；要透明背景用 webm+vp9 时再开。
gop / codec / yieldEvery / onLog / muxerUrls…高级项：关键帧间隔 / 强制 H.264 codec 串 / 让出主线程频率 / 日志回调 / 自定义 muxer CDN。

踩坑清单 · 库已替你兜住的 & 你要知道的

▸ 偶数宽高

H.264 要求宽高为偶数，否则编码直接报错。库内部 even() 自动对齐，你传 1081 也能跑。

▸ 跨域图污染

render 里 drawImage 跨域且无 CORS 头的图会污染 canvas，导致黑帧/SecurityError。请用同源图或带 crossOrigin='anonymous' 且服务端允许 CORS 的图。库对单帧 try/catch，但污染是 canvas 级的——源头要干净。

▸ 需安全上下文

WebCodecs 仅在 https 或 localhost 可用。file:// 双击打开通常没有 → auto 模式会自动回退 MediaRecorder（仍可能受限）。部署到任意静态托管即可满血。

▸ 时长精确性

WebCodecs 逐帧离线，时长严格 = 帧数/fps，渲染再慢也不丢帧。MediaRecorder 是实时墙钟录制，渲染卡顿会让成片偏短——这是兜底，能跑就行。

▸ render 要画满

库不会替你清屏/填底（避免覆盖透明意图）。alpha:false 时未画区域是黑边。请在 render 第一行 fillRect 铺满背景。

▸ 一帧炸 ≠ 全片炸

render 或 encode 单帧抛错只跳过该帧并写 onLog，循环继续。不会因一帧异常中断整段导出。

▸ 让出主线程

WC 循环每 yieldEvery 帧 setTimeout(0)，否则进度回调不刷新、页面假死。默认 3，别设太大。

▸ Safari / 老浏览器

Safari 的 VideoEncoder 支持较晚；不支持时 auto 自动走 MediaRecorder。用 VEX.isWebCodecsSupported() 提前判断做 UI 提示。

三种接入方式

<script>

把库存成 video-exporter.js，<script src="video-exporter.js"> 后用全局 exportVideo / VEX。零构建，最省心。

ESM / import

UMD 头已兼容打包器：import { exportVideo } from './video-exporter.js'（或 require）。

内联

单文件项目可直接把库源码贴进 <script>。本页「复制 video-exporter.js」拿到的就是干净源码。
